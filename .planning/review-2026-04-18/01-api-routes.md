# API Routes & Server Actions Review

**Reviewed:** 85 route files + 2 server actions
**Date:** 2026-04-18

## Summary

The surface is large (85 routes) and auth is applied inconsistently — roughly 30 routes use `auth()`, but most read/write endpoints do not. The known `brandProfile.findFirst({ where: { isActive: true } })` pattern is confirmed and appears in at least **four** routes, exposing any authenticated user's brand profile (voice, audience, positioning, pain points) to any unauthenticated caller. Several mutation endpoints are completely unauthenticated (`PATCH`/`DELETE /api/ad-library/brands/[pageId]`, full Hikaru chat CRUD, `POST /api/ad-library/jobs cleanup-stale`, `POST /api/manus/*`). Cost exposure is severe — most of the LLM-calling routes (Claude Sonnet iterated 15×, Gemini image gen, Replicate image gen, Manus deep-research) have no auth, no rate limit, and no user-level budget cap; with the shared production DB this is a credit-burn vector accessible from the open internet. Cron endpoints fail open when `CRON_SECRET` is unset, and the `POST` variant of the ingest cron has no secret check at all.

The credentials provider accepts a hardcoded `demo@example.com / demo123` pair that is publicly advertised on `/auth/signin` and happens to be listed in the admin allow-list for roadmap moderation, so anyone on the internet can authenticate as the "admin" user.

## Findings

### P0 — ship-blockers

- **[Auth bypass] Demo credentials = admin** — `src/auth.ts:17-23` + `src/app/api/roadmap/[id]/route.ts:6` — `demo@example.com / demo123` is a real, documented login (placeholder shown on `src/app/auth/signin/page.tsx:156,197`) and that same email is in `ADMIN_EMAILS`. Anyone on the internet can log in and PATCH/DELETE any roadmap request, approve brand requests, etc. Also, the second admin address `sebastian@kirimediagroup.com` does not match the user's actual email `sebastian@kirimedia.co` (per MEMORY.md), so the real admin cannot moderate. Fix: remove credentials provider in prod (or gate behind env flag), correct admin email, and move admin check to a proper role/column.
- **[IDOR] `brandProfile.findFirst({ isActive: true })` leaks any user's profile** — confirmed the flagged finding at `src/app/api/strategy/personalized/route.ts:56-68` and the same pattern in `src/app/api/strategy/[pageId]/route.ts:66-76`, `src/app/api/brand-health/route.ts:163-208`, and the Manus fallback in `src/app/api/chat/hikaru/route.ts:1031-1044` (accepts arbitrary `brandProfileId` with no ownership check). None of these routes require auth; all return/use the active BrandProfile of whatever user happens to match, which includes audience demographics, pain points, brand voice, positioning, colors, logo URL, reference images, and competitor links. Fix: require `auth()` + `where: { userId: session.user.id, isActive: true }` in every `brandProfile` lookup.
- **[Auth bypass] Public ability to mutate or delete ANY brand** — `src/app/api/ad-library/brands/[pageId]/route.ts:432-558` (PATCH) and `:565-603` (DELETE). No auth at all. Anyone can rename a brand, set `ingestionStatus='paused'`, or `DELETE` which cascades through ads, assets, ingestion jobs, classifications. Fix: require auth + admin role.
- **[Auth bypass] Hikaru chat history is globally public** — `src/app/api/chat/hikaru/history/route.ts:7-31` lists ALL chats to anyone; `src/app/api/chat/hikaru/history/[chatId]/route.ts:7-39` lets anyone GET/DELETE any chat by ID; `src/app/api/chat/hikaru/history/[chatId]/messages/route.ts:7-59` lets anyone write messages into any chat. `HikaruChat` has no `userId` column at all. Fix: add `userId` to model, require auth, filter by session user.
- **[IDOR + cost] Hikaru chat accepts arbitrary `brandProfileId`** — `src/app/api/chat/hikaru/route.ts:943-1049` takes `brandProfileId` from request body, does `findUnique({ where: { id } })` with no ownership check, and injects another user's `compileBrandContext(profile)` into both the Claude system prompt and the Manus task body. No auth on the route at all. Also runs up to 15 iterations × 4096-token Sonnet calls + 10 database tools per request, publicly, with no rate limit. Fix: require auth, filter brandProfile by userId, add per-user rate limit + iteration cost cap.
- **[Cost] Cron routes fail open when CRON_SECRET is not set** — `src/app/api/ad-library/cron/ingest/route.ts:1180`, `cron/assets/route.ts:16`, `cron/classify-poll/route.ts:15`, `cron/sov-snapshot/route.ts:20`. All use the pattern `if (CRON_SECRET && authHeader !== Bearer ${CRON_SECRET})`. If the env var is missing/misspelled in prod, the secret check is *skipped* and the cron is publicly callable. Each of these does heavy work (Facebook API calls across all pending brands, Anthropic batch polling, R2 uploads). Fix: fail closed — `if (!CRON_SECRET || authHeader !== ...)`.
- **[Cost] `POST /api/ad-library/cron/ingest` has NO secret check** — `src/app/api/ad-library/cron/ingest/route.ts:1246-1371`. The `POST` manual-trigger variant completely skips the Vercel cron secret and accepts `brandIds`, `limit`, and `resetTokens` from any caller. Anyone can reset all Facebook token rate-limit state (`resetTokens: true`) or force re-ingestion of any brands, burning through the shared Facebook API token pool. Fix: same secret gate as GET (or admin auth).
- **[Cost] Manus endpoints are unauthenticated and accept arbitrary brandProfileId** — `src/app/api/manus/create/route.ts:8-59` and `src/app/api/manus/enrich/route.ts:7-106`. Any unauthenticated caller can fire Manus "deep research" tasks (2-5 minute paid tasks) with any prompt, and the enrich endpoint will *overwrite fields* on a brand profile owned by someone else (`src/app/api/manus/[taskId]/route.ts:149-237` later writes `brandVoice`, `demographics`, etc. based on whatever the Manus result text contained). Fix: require auth + verify profile ownership before creating a task or merging results.
- **[Cost] Hikaru and `/api/chat` burn Claude Sonnet unauthenticated** — `src/app/api/chat/hikaru/route.ts:1067-1073` runs up to 15 Sonnet iterations of 4096 tokens with 10 Prisma-tool calls each; `src/app/api/chat/route.ts:404-445` runs up to 5 iterations. Neither checks auth, has a rate limit, or a spend cap. Given that `CRON_SECRET`/auth-required routes are the only protected surface, these are the cheapest DoS vector to burn the Anthropic bill. Fix: require auth, add per-IP/per-user rate limit, cap iterations×tokens by tier.
- **[Cost] `/api/analyze` can trigger mass paid analysis by anyone** — `src/app/api/analyze/route.ts:230-449`. Accepts a `category` or `brandId`, fetches up to 30 ads × Haiku vision calls, then a Sonnet 4096-token `generateTemplates` call, all unauthenticated, and persists results to shared DB. Fix: auth + rate limit.
- **[Cost] `/api/creative-lab/generate-strategy` unauthenticated Sonnet chain** — `src/app/api/creative-lab/generate-strategy/route.ts:74-146`. WIP route intentionally skipped typecheck (commit e88c795 `@ts-nocheck` at line 1). Has no auth and does three sequential Sonnet 4000-token calls. Fix: auth + user-level budget.
- **[Cost] `/api/classify/inline` and `/api/classify/batch` are unauthenticated** — `src/app/api/classify/inline/route.ts:17-139` (runs up to 50 Haiku vision calls per request, no auth); `src/app/api/classify/batch/route.ts:12-107` (submits a full Anthropic batch job for all unclassified ads of a brand, no auth). Combined with the unauth `PATCH` on brands, anyone can drive Anthropic spend against the shared API key. Fix: auth + tier-based caps.
- **[Cost] `/api/analyze/generate-image` hits Replicate unauthenticated** — `src/app/api/analyze/generate-image/route.ts:39-128`. `useBrandGuidelines` is the only session-gated branch; the main Flux Schnell image generation requires no session. Same pattern in `/api/creative-lab/generate-batch` (Gemini image gen) and `/api/analyze/generate` (Haiku).
- **[Cost] `/api/ad-library/brands/[pageId]/copy-analysis` unauthenticated Claude Haiku** — `src/app/api/ad-library/brands/[pageId]/copy-analysis/route.ts:146-381`. Has an *in-memory* 24h cache keyed by pageId, but any new pageId triggers a 4000-token Haiku call with 100 ad samples. Also, because the cache is in-memory it is per-instance and ineffective on Vercel.
- **[Data loss] `POST /api/ad-library/jobs` cleanup-stale is unauthenticated** — `src/app/api/ad-library/jobs/route.ts:102-132`. Any caller can POST `{"action":"cleanup-stale"}` and mark every currently-running ingestion job as `failed`. Fix: secret or admin auth.
- **[Cost/SSRF] Unauthenticated `/api/search-pages` fans out 8 Facebook API calls** — `src/app/api/search-pages/route.ts:56-82`. Each request with a new query burns 8 `ads_archive` requests in parallel (Nordic + EU countries) using shared tokens. No auth, no rate limit. Combined with token rotation cost tracking, this is a free accelerator to hit Facebook rate limits. Same pattern in `POST /api/requests` `search` branch (`src/app/api/requests/route.ts:68-106`, 6 countries).
- **[IDOR] `/api/creative-lab/generate-config` and `generate-brief` accept `pageId` and may pull any user's brand profile into Gemini/Claude prompts** — `src/app/api/creative-lab/generate-config/route.ts:77-109` and `src/app/api/creative-lab/generate-brief/route.ts:78-99`. These DO gate brand-profile injection on `session?.user?.id`, but the rest of the endpoint (the Gemini Visual Bible call + Claude creative director Sonnet call) runs unauthenticated. So they are both (a) cost exposure and (b) `useBrandGuidelines` isn't configurable — if a malicious authenticated user calls with someone else's pageId they still get expensive output.

### P1 — important

- **[Auth] `/api/ad-library/assets/backfill` unauthenticated data mutation** — `src/app/api/ad-library/assets/backfill/route.ts:11-54`. Anyone can POST and create up to 500 AdAsset rows marked `pending`, which the asset cron will then download via R2 (bandwidth cost).
- **[Auth] `/api/ad-library/assets` POST is unauthenticated** — `src/app/api/ad-library/assets/route.ts:39-` triggers `processPendingAssets` (Puppeteer → R2 upload) on demand.
- **[Auth] `/api/ad-library/export` lets anyone download up to 10,000 rows with filters** — `src/app/api/ad-library/export/route.ts:261-333`. No auth, no rate limit — scrapable full-text ad DB dump.
- **[IDOR via `isActive`] `src/app/api/creative-lab/generate-brief/route.ts:81-84` still uses `findFirst({ userId, isActive: true })`** — OK when session exists, but falls back silently when not (`catch {}`), so there's no hard requirement that the session user even owns the brand being briefed. Lower severity than the P0 pattern but worth aligning.
- **[PII leak] `/api/roadmap` GET leaks user emails to anyone** — `src/app/api/roadmap/route.ts:40-52` returns `userEmail: r.userEmail` for every request to any unauthenticated caller. Fix: only return userEmail for admins or the submitter.
- **[Input validation] No zod on most high-blast-radius routes** — e.g. `src/app/api/classify/batch/route.ts:12-22`, `classify/inline/route.ts:19-31`, `analyze/route.ts:232-248`, `ad-library/brands/[pageId]/route.ts PATCH:432-551`, `dashboard/snapshots/route.ts:17-20`, `dashboard/competitors/route.ts:28-46`, `brands/save/route.ts:14-31`. Body is cast with `as { ... }`. Missing type checks → runtime 500s, occasionally data corruption.
- **[Input validation] `/api/ad-library/ads` `isActive`, `publisherPlatforms`, `category`, etc. come straight from query string without validation** — `src/app/api/ad-library/ads/route.ts:120-189`. Date parsing uses `new Date(filters.startDateFrom)` with no NaN guard — invalid input leads to a Prisma crash / 500.
- **[IDOR] `/api/ad-library/saved/check` and `/api/ad-library/brands/monitor/check` accept unbounded `adIds`/`brandIds` array** — `src/app/api/ad-library/saved/check/route.ts:24-34` and monitor/check — a caller can submit a 100k-element array and Prisma will `IN (?)` over it. DoS vector. Fix: `z.array(z.string()).max(100)`.
- **[Input validation / unbounded take] `/api/chat/hikaru/route.ts searchAds` and `getCreativeAnalysis`, `getAdTemplates`, `searchCreators` tool wrappers take limits up to 25 or 50** — reasonable individually but the outer loop does 15 iterations, so a single chat request can trigger `15 * 50 = 750` Prisma rows/tool returned plus 15 Sonnet calls.
- **[Prisma safety] Unbounded `findMany` with no take** — `src/app/api/ad-library/brands/[pageId]/reach-timeline/route.ts:66-76` (all ads for a brand), `/api/categories/route.ts:8-18` (all branded brands), `/api/categories/[slug]/route.ts:15-28`, `/api/brand-health/route.ts:128-137` (`brandAnalysisCache.findMany` with `in: competitorBrandIds`). Fine now but will degrade silently.
- **[Error leak] Most routes return raw `error.message` or `String(error)` to the client** — pattern appears throughout (e.g. `src/app/api/brand-profiles/route.ts:77,150`, `brand-guidelines/route.ts:51`, `ad-library/ads/route.ts:485-489`, `ad-library/brands/[pageId]/route.ts:408,553,596`). This leaks Prisma query internals, token partials, and stack-adjacent data. Fix: return generic `{ error: "Internal error" }` + log server-side; only surface validation errors.
- **[Error shape] Feedback endpoint leaks Notion API error body** — `src/app/api/feedback/route.ts:65-82` returns `details: errorText` directly from Notion — may expose database schema or access token hints if misconfigured.
- **[No rate limit] `/api/signup` and `/api/feedback` are open-internet Notion-DB writers with only email-regex validation** — `src/app/api/signup/route.ts:10-82`, `feedback/route.ts:12-91`. Trivial to spam the Notion database. Fix: Cloudflare Turnstile, per-IP limiter, or server-side Notion queue with dedup.
- **[CSRF-adjacent] State-changing GET on `/api/manus/[taskId]`** — `src/app/api/manus/[taskId]/route.ts:7-106` performs `prisma.manusTask.update` + potentially writes into `brandProfile` (via `mergeWebsiteEnrichment`) from a GET. Any cross-origin embed / prefetch could mutate. Convert to POST or require explicit polling via state machine.
- **[CSRF-adjacent] `/api/ad-library/cron/assets` GET triggers real downloads** — same shape; fine while the secret gate holds, but see the fail-open issue in P0.
- **[Validation / SSRF bypass] `/api/creative-lab/scrape-brand` private-IP check is string-based** — `src/app/api/creative-lab/scrape-brand/route.ts:13-35` blocks `localhost`, `0.0.0.0`, and a few IPv4 ranges by hostname match, but no DNS resolution. An attacker can use `internal.attacker.com` → A record `169.254.169.254` (EC2 metadata), or `169.254.169.254` literally (not in the block list), or any IPv6 localhost (`::1`, `fc00::/7`). Fix: resolve DNS and block via Node `dns.lookup` before fetch, and include link-local / IPv6 ranges.
- **[Token exposure] `/api/facebook-ads` accepts `accessToken` from client body** — `src/app/api/facebook-ads/route.ts:163-170,282`. Pattern `getAccessToken(body.accessToken)` allows a caller to supply their own FB token (benign) but there's no validation it's actually theirs, and the same route will fall back to server tokens if the body one is rejected — the tier-enforcement limit check still happens before this, but a body-supplied token bypasses the rate-managed pool.
- **[Cost tracking scoping] `/api/brand-profiles/[id]/enrich` uses global `getDailySpend()` for budget** — `src/app/api/brand-profiles/[id]/enrich/route.ts:136-145`. The $2/day cap is global across all users, so one user can block everyone else. Make it per-user.
- **[Prisma N+1] `/api/categories/[slug]` fans out per-brand aggregates in `Promise.all` over all brands** — `src/app/api/categories/[slug]/route.ts:35-58`. With many brands this is 3 queries per brand. Same pattern in Hikaru `getCategoryInsights` (`chat/hikaru/route.ts:497-516`).
- **[Auth] `/api/ad-library/jobs` GET is unauthenticated** — operational metadata (error messages, completion times, brand names) of ingestion pipeline exposed.
- **[Auth] `/api/ad-library/brands/monitor/check` returns empty `[]` to unauthenticated callers** (`src/app/api/ad-library/brands/monitor/check/route.ts:15-17`) rather than 401 — inconsistent with the other saved-ads pattern and easy to mis-use client-side.
- **[Server action] `analyzeSitemap` server action has no auth and fetches arbitrary user-supplied URLs** — `src/actions/analyze-sitemap.ts:29-72`. SSRF risk via sitemap fetch (calls `fetchAllSitemapURLs` which follows sitemap-index links). No bound on total URLs crawled.
- **[Admin emails hardcoded twice] — `src/app/api/roadmap/[id]/route.ts:6` and `src/app/roadmap/page.tsx:28` both hardcode `ADMIN_EMAILS`. Drift risk; move to env/DB.

### P2 — nits

- **Cron route returns 200 even when webhook processing fails** — `src/app/api/webhooks/stripe/route.ts:89-97`. Deliberate (comment explains avoiding Stripe retries), but means silent data-sync drift. At minimum log to an error tracker.
- **[Error handling] Several routes swallow Claude parse errors and retry once** — `src/app/api/creative-lab/generate-strategy/route.ts:576-629` retries with a modified prompt (good), but many others don't (`/api/strategy/personalized/route.ts:130-150`, `/api/analyze/diversity/route.ts:404-405`).
- **[Error handling] `try/catch` with empty `catch {}` that hides real failures** — `scrape-brand/route.ts:167-172` (whole handler returns `nullResult` on any failure), `/api/creative-lab/generate-brief/route.ts:97-99`, etc. Harder to diagnose incidents.
- **[Response shape] Inconsistent error shape** — some routes return `{ error: string }`, others `{ success: false, error }` (`/api/facebook-ads/route.ts`), others `{ error, details }` (`brand-profiles/route.ts`). Standardize.
- **[Status codes] `unauthorized` returned as 500 in several error paths due to `String(error)` catch** — `brand-profiles/route.ts:77,150`.
- **[Hardcoded constants] `NOTION_DATABASE_ID` and R2 public URL hardcoded in source** — `src/app/api/signup/route.ts:3`, `feedback/route.ts:4`, `analyze/route.ts:10`. Move to env.
- **[Ingestion] `upsertAd` inside `processBrand` is sequential (`for await`)** — `src/app/api/ad-library/cron/ingest/route.ts:1107-1112`. For 2000 ads this will often hit the Vercel 300s cap on the `maxDuration = 300` route.
- **[Const mistake] `getSubscriptionStatus` call with `past_due` gets treated as Pro** — `src/app/api/brands/save/route.ts:35` (`status === 'pro' || status === 'past_due'`). Unusual; normally past_due is grace period only.
- **[Typecheck skip] `generate-strategy` has `@ts-nocheck`** — `src/app/api/creative-lab/generate-strategy/route.ts:1`. Per commit e88c795 this is intentional WIP, but it's routed publicly. Either guard with a feature flag or keep behind auth + feature flag.
- **[DRY] Three nearly-identical chat tool sets live in `src/app/api/chat/route.ts`, `chat/hikaru/route.ts`, and elsewhere — maintenance burden plus inconsistent `limit` caps.
- **[Unused/hidden] Dashboard `/api/dashboard/feed` returns different shape depending on auth, with no error for unauth** — fine by design, but makes response typing awkward.

## Patterns worth addressing globally

- **Auth inconsistency:** Of 85 routes, ~30 call `auth()`. The rest assume public access, but many of them mutate data or call paid APIs. There is no middleware enforcing auth by default. Recommend: middleware allow-list (public routes explicitly opted in) rather than the current opt-in `auth()` pattern.
- **No rate limiting anywhere:** I saw zero middleware or library-level rate limiting (no `@upstash/ratelimit`, no token-bucket). Combined with the many unauthenticated LLM routes, this is the single largest cost/security risk. Add a per-IP bucket for anonymous endpoints and a per-user bucket for all LLM-calling paid endpoints.
- **`prisma.brandProfile.findFirst({ where: { isActive: true } })` IDOR pattern:** Four confirmed copies (strategy/personalized, strategy/[pageId], brand-health, hikaru's Manus branch). Audit every `prisma.brandProfile.find*` call; none should run without the authenticated user ID scoped in the `where`. Same comment applies to `trackedBrand` — mostly scoped correctly, but the pattern is brittle.
- **No zod at all on many POST/PATCH bodies:** Where zod exists (`brand-profiles/*`, `brand-guidelines`, `creative-lab/scrape-brand`, a few others) it's well-used; elsewhere handlers destructure raw JSON with `as` casts. Adopt a project-wide rule: "if it has a body, it has a zod schema."
- **Error messages leak internals:** `String(error)` and `error.message` are returned to clients in >40 routes. Adopt a `sanitizeError(err)` helper that returns `{ error: "Internal server error" }` for anything that isn't a known validation failure, and always logs the full error server-side.
- **Cron secret "fail-open" idiom:** `if (SECRET && header !== Bearer SECRET) return 401` is used in every cron route. Should be `if (!SECRET || header !== Bearer SECRET) return 401`, otherwise a missing env var silently disables auth.
- **Shared production DB means every unauthenticated mutation is high-blast-radius:** `PATCH /api/ad-library/brands/[pageId]` lets an attacker trigger `onDelete: Cascade` of entire brand trees in production from `localhost`.
- **LLM cost tracking exists (`logApiCost`, `getDailySpend`) but is only wired into a few routes (classify-*, enrich).** Wire it everywhere a client.messages.create / genAI call is made, and enforce per-user (not global) caps.
- **Hikaru + chat endpoints trust body-supplied `brandProfileId` for context injection.** Always re-verify ownership server-side from the session before reading BrandProfile or TrackedBrand data.
- **SSRF prevention strings-only:** scrape-brand, analyze-sitemap, and the website enrichment prompt construction all take user-supplied URLs. None resolve DNS before fetch; none block IPv6 loopback or cloud metadata endpoints.
