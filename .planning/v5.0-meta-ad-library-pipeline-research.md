# v5.0 Meta Ad Library Pipeline Research

**Goal:** Build a data pipeline that continuously ingests ad creatives and metadata from Meta's Ad Library for European brands with 30+ active ads, stores them in a searchable database with re-hosted media, and exposes them through a research-oriented interface.

**Use cases:**
- Research ad creative trends across thousands of European brands
- Track ad creative evolution over time for specific brands
- Search and filter ads by copy, format, platform, country, and date
- Export filtered datasets for external analysis

---

## Feature Overview

### Core Workflow

1. **API Setup** — Get Meta Ad Library API access with ads_read permissions
2. **Brand Discovery** — Build and maintain list of European brands with 30+ active ads
3. **Ingest Ads** — Fetch ad creatives and metadata, store in database
4. **Store Media** — Download and re-host images/videos on S3/CDN
5. **Search & API** — Full-text search and filtered queries over ingested data
6. **Research UI** — Browse, filter, and export ad data

---

## Phase 1 — Meta Ad Library API Access & Setup

**Goal:** Get authenticated access to Meta's Ad Library API.

### Tasks

1. Create a Facebook App in Meta Developer portal (or use existing)
2. Apply for Ad Library API access — select "research" as use case
3. Once approved, generate long-lived access token with `ads_read` permissions
4. Test basic queries: fetch ads for known European brand by Page ID
5. Document rate limits (typically ~200 calls/hour/token, verify against actual tier)

### Deliverable

Working API token that can query and return ad data for any given Page ID.

### API Response Fields

Per-ad data from Meta Ad Library API:
- `ad_id` — Unique ad identifier
- `page_id`, `page_name` — Brand/page info
- `ad_creative_body`, `ad_creative_link_caption`, `ad_creative_link_title`, `ad_creative_link_description` — Copy fields
- `call_to_action.type`, `call_to_action.value` — CTA data
- `ad_snapshot_url` — Link to ad snapshot
- `publisher_platforms` — Array: facebook, instagram, messenger, audience_network
- `ad_delivery_start_time`, `ad_delivery_stop_time` — Date range
- `ad_creative_bodies`, `ad_creative_link_captions` — Array variants (DPA/carousel)
- `images`, `videos` — Media URLs
- `estimated_audience_size` — Reach estimate
- `impressions`, `spend` — Performance data (if available)

## Phase 3 — Database & Storage Design

**Goal:** Design the schema and storage infrastructure.

### Database Schema

```prisma
model AdLibraryAd {
  id                String   @id @default(cuid())
  adId              String   @unique  // Meta's ad_id

  // Brand relation
  brandId           String
  brand             AdLibraryBrand @relation(fields: [brandId], references: [id], onDelete: Cascade)

  // Creative content
  displayFormat     String?  // image, video, carousel, dpa
  publisherPlatforms String[] // facebook, instagram, messenger
  body              String?  // Primary ad copy
  caption           String?
  title             String?
  linkDescription   String?
  linkUrl           String?
  ctaText           String?
  ctaType           String?

  // Dates
  startDate         DateTime?
  endDate           DateTime?
  adDurationDays    Int?
  isActive          Boolean  @default(true)

  // Performance (if available)
  reachEstimate     Int?
  impressionsLower  Int?
  impressionsUpper  Int?
  spendLower        Float?
  spendUpper        Float?

  // Metadata
  ingestionJobId    String?
  ingestionJob      IngestionJob? @relation(fields: [ingestionJobId], references: [id])
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  assets            AdAsset[]
}

model AdAsset {
  id              String   @id @default(cuid())

  adId            String
  ad              AdLibraryAd @relation(fields: [adId], references: [id], onDelete: Cascade)

  assetType       String   // image, video, thumbnail
  originalUrl     String   // Meta CDN URL
  storedUrl       String?  // Our CDN URL
  storedKey       String?  // S3 key
  thumbnailUrl    String?  // Generated thumbnail URL
  thumbnailKey    String?  // S3 key for thumbnail

  fileExtension   String?
  fileSizeBytes   Int?
  width           Int?
  height          Int?

  createdAt       DateTime @default(now())
}

model IngestionJob {
  id              String   @id @default(cuid())

  brandId         String
  brand           AdLibraryBrand @relation(fields: [brandId], references: [id], onDelete: Cascade)

  status          String   @default("queued") // queued, running, completed, failed
  adsFetched      Int      @default(0)
  assetsDownloaded Int     @default(0)
  errors          String?  // JSON array of error messages

  startedAt       DateTime?
  completedAt     DateTime?
  createdAt       DateTime @default(now())

  ads             AdLibraryAd[]
}
```

### Media Storage

- **S3-compatible storage:** AWS S3, Cloudflare R2, or MinIO
- **Key structure:** `assets/{ad_id}/{asset_id}.{ext}` and `assets/{ad_id}/{asset_id}_thumb.{ext}`
- **CDN:** CloudFront or Cloudflare for serving
- **Thumbnails:** Generate on ingest (400px wide for images, first-frame for videos)

### Deliverable

Database migrated and storage buckets provisioned with CDN configured.

## Phase 4 — Ingestion Pipeline

**Goal:** Build the core pipeline that fetches ads from Meta and stores them.

### Pipeline Steps (per brand)

1. Query Meta Ad Library API for brand's Page ID, paginate through all results
2. For each ad: upsert metadata into `ads` table, detect new/changed/stopped ads
3. For each ad's creative assets:
   - Download images/videos from Meta's CDN
   - Generate thumbnail (400px for images, first-frame for videos)
   - Upload originals and thumbnails to S3
   - Store storage keys and URLs in `ad_assets`
4. Update brand's `lastSyncedAt` and `activeAdCount`
5. Log everything to `ingestion_jobs` table

### Technical Considerations

- **Job queue:** BullMQ, Celery, SQS, or similar for managing ingestion jobs
- **Rate limiting:** Exponential backoff, token bucket / leaky bucket rate limiter
- **Pagination:** Meta uses cursor-based pagination
- **Concurrency:** Cap parallel downloads (e.g., 10 per job) to avoid overwhelming network
- **Idempotency:** Jobs should be resumable without duplicating data
- **Large files:** Videos can be 50MB+; stream to disk/S3, don't buffer in memory

### Refresh Schedule

- Full sync per brand once or twice daily
- Prioritize brands with higher ad counts or faster turnover
- Flag ads as inactive when they disappear from API response

### Deliverable

Working pipeline that can ingest all ads for a brand, store metadata and media, triggered on schedule.

## Phase 5 — Search & API Layer

**Goal:** Make ingested data searchable and accessible.

### API Endpoints

```
GET  /api/ad-library/search
     ?q=keyword          — Full-text search in body, caption, title
     &brand=pageId       — Filter by brand
     &platform=facebook  — Filter by platform
     &format=video       — Filter by format
     &status=active      — Filter by active/inactive
     &country=DE         — Filter by country
     &dateFrom=2024-01   — Filter by start date
     &dateTo=2024-12     — Filter by end date
     &sort=date|relevance|duration
     &page=1&limit=50

GET  /api/ad-library/brands
     — List all brands with ad counts

GET  /api/ad-library/brands/:pageId
     — Get brand details and recent ads

GET  /api/ad-library/ads/:adId
     — Get single ad with all assets and metadata

GET  /api/ad-library/export
     ?format=csv|json
     &...filters         — Export filtered results
```

### Full-Text Search

Index ad copy fields in search engine:
- PostgreSQL full-text search (simple, built-in)
- Elasticsearch (powerful, complex)
- Meilisearch or Typesense (modern, easy to deploy)

### Media Serving

- Serve media through CDN URLs, not directly from S3
- Signed URLs if access control needed

### Deliverable

Functional API supporting search, filter, sort, paginate, and export.
