1. Import TAXONOMY from `./taxonomy` and dynamically build category descriptions from `TAXONOMY[key].values` and `TAXONOMY[key].labels` so the prompt stays in sync with taxonomy changes.
2. For each of the 8 categories, list every value with a short 1-line description of when to use it (these go beyond the display labels -- they should explain the distinction between similar values).
3. Include 5 few-shot examples that cover a range of ad types:
   - Example 1: Studio product demo (e.g., Nike running shoe ad) -- product-aware, aspirational
   - Example 2: UGC testimonial (e.g., skincare before/after) -- solution-aware, social-proof
   - Example 3: Graphic design with discount offer (e.g., SaaS flash sale) -- most-aware, urgency-scarcity
   - Example 4: Lifestyle skit (e.g., DTC brand day-in-life) -- unaware/problem-aware, emotional
   - Example 5: Text-overlay listicle (e.g., supplement benefits list) -- solution-aware, educational

   - Every field is required. Pick the BEST match from allowed values.
   - Use "other" only when no value fits at all.
   - hookScore: 1-3 = weak/generic, 4-6 = decent, 7-10 = strong scroll-stopper.
   - conceptCluster: reuse the SAME label for ads with the same core concept. Keep labels lowercase, hyphenated, 2-3 words.
   - confidence: honest estimate (0.5 = guessing, 0.9+ = very confident).

Build the prompt as a template literal that interpolates TAXONOMY values dynamically. Export as a function `buildClassificationPrompt()` that returns the string, so it can be called at runtime (not a module-level constant that imports at parse time).

Also export a helper function `buildAdContext(ad: { brandName?: string; category?: string; body?: string; title?: string; ctaText?: string; displayFormat?: string }): string` that formats ad data into the user message format expected by the prompt.   <files>src/lib/classification/cost-tracker.ts</files>
  <action>
Create `src/lib/classification/cost-tracker.ts` with two exported functions:

**1. `logApiCost(entry: CostEntry): Promise<void>`**

```typescript
interface CostEntry {
  model: string;
  operation: string; // "classify-single", "classify-batch", "strategy-gen", etc.
  inputTokens: number;
  outputTokens: number;
  brandId?: string;
}
```

Implementation:
- Define a PRICING map with per-million-token costs:
  - `claude-haiku-4-5-20251001`: input $1.00, output $5.00
  - `claude-sonnet-4-6-20260327`: input $3.00, output $15.00
  - Default fallback: input $3.00, output $15.00
- Calculate `estimatedCost` from token counts and pricing
- Get today's date truncated to midnight (set hours/min/sec/ms to 0)
- Insert into `prisma.apiCostLog.create()` with all fields
- CRITICAL: Wrap the entire function body in try/catch. On error, `console.error("Failed to log API cost:", error)` but do NOT throw. This is fire-and-forget -- a cost logging failure must never break classification.

**2. `getDailySpend(): Promise<number>`**

- Get today's date truncated to midnight
- Use `prisma.apiCostLog.aggregate()` with `where: { date: { gte: today } }` and `_sum: { estimatedCost: true }`
- Return the sum or 0 if null

**3. `getSpendByOperation(days: number = 7): Promise<Record<string, number>>`**

- Get date N days ago
- Use `prisma.apiCostLog.groupBy()` with `by: ['operation']`, `where: { date: { gte: startDate } }`, `_sum: { estimatedCost: true }`
- Return a Record mapping operation name to total spend

Import prisma from `@/lib/prisma` (the existing prisma client).

Do NOT use `after()` from Next.js here -- keep it as a simple async function. The caller (Phase 63) will decide whether to fire-and-forget or await.
  </action>
  <verify>Run `npx tsc --noEmit` to confirm no type errors. Verify the file imports prisma correctly. Verify logApiCost has try/catch wrapping (grep for "catch" in the file). Verify PRICING map has at least 2 model entries.</verify>
  <done>cost-tracker.ts exports logApiCost (fire-and-forget with error swallowing), getDailySpend (today's total), and getSpendByOperation (breakdown by operation over N days). All functions use the existing prisma client and the ApiCostLog model from Plan 01.</done>
