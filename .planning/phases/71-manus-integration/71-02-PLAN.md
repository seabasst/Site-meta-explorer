    **Hikaru route modification** (`src/app/api/chat/hikaru/route.ts`):

    Add routing pre-check at the TOP of the POST handler, BEFORE the existing Claude SSE flow:
    1. Import `shouldRouteToManus` from `@/lib/manus/router` and `createManusTask` from `@/lib/manus/client`
    2. Parse `deepResearch` boolean from request body (alongside existing `messages` and `brandProfileId`)
    3. Extract last user message content
    4. Call `shouldRouteToManus(lastMessage, deepResearch)`
    5. If true:
       - Build Manus prompt: include brand context if available (use `compileBrandContext()` output as prefix to the user's message)
       - Call `createManusTask(manusPrompt)`
       - Save to DB via `prisma.manusTask.create()` with `manusTaskId`, `brandProfileId`, `prompt`, `status: 'running'`, `manusUrl`
       - Return a JSON response (NOT SSE stream): `{ type: 'manus_task', taskId: task.id, manusTaskId: result.task_id, message: 'Deep research started. This usually takes 2-5 minutes.' }`
       - This is a normal `Response.json()` — the client detects `type: 'manus_task'` and switches to polling mode
    6. If false: the existing Claude SSE flow continues completely unchanged

    CRITICAL: Do NOT modify the existing Claude SSE streaming logic. The Manus routing is a short-circuit that returns early. All existing code paths remain identical.

    **Hikaru page UI modification** (`src/app/dashboard/v2/hikaru/page.tsx`):

    1. **Deep Research toggle**: Add a toggle button next to the send button in the chat input area. Use a `Sparkles` or `Search` icon from lucide-react. When active, show a blue highlight/badge. State: `const [deepResearch, setDeepResearch] = useState(false)`.

    2. **Send with deepResearch flag**: In the `sendMessage` function, add `deepResearch` to the fetch body: `body: JSON.stringify({ messages: ..., brandProfileId: ..., deepResearch })`.

    3. **Detect Manus response**: After the fetch call, check if the response Content-Type is JSON (not event-stream). If JSON, parse it and check for `type === 'manus_task'`. If so, switch to polling mode instead of reading SSE stream.

    4. **Manus message type**: Extend the `Message` interface to support async results:
       ```
       interface Message {
         role: 'user' | 'assistant';
         content: string;
         steps?: ThinkingStep[];
         manusTaskId?: string;        // If this is a Manus deep research result
         manusStatus?: 'running' | 'completed' | 'failed';
       }
       ```

    5. **Polling hook**: Create a `useManusTask` hook (inline in the page file, not a separate file):
       - Takes `taskId: string | null`
       - Polls `GET /api/manus/${taskId}` every 5 seconds
       - Updates message content when completed
       - Clears interval on completed/failed
       - Returns `{ status, resultText }`

    6. **Manus polling card in chat**: When a message has `manusTaskId` and status is `running`, render an inline card instead of regular text:
       - Show animated spinner with "Researching... this usually takes 2-5 minutes"
       - Show elapsed time since request started (use a simple counter)
       - When completed: replace card with the resultText rendered as regular markdown
       - When failed: show error state with "Research failed. Try again or use a simpler query."

    7. **Flow**: User sends message -> routing detects deep research -> returns task ID -> assistant message created with `manusTaskId` + `status: 'running'` -> polling card renders -> poll completes -> message content updated with results -> polling card replaced with rendered text.

    8. **Save Manus results to history**: When a Manus task completes, call the existing `saveMessages()` function with the final result content, so it persists in chat history.

    Design notes (dark mode, follows existing Hikaru page patterns):
    - Toggle button: small pill/icon button, uses `bg-[#1235e2]` when active, `bg-transparent` when off
    - Polling card: rounded-xl, border, subtle pulse animation on the spinner
    - Match existing ThinkingSteps visual language for the in-progress state

    Create POST handler for website-based brand profile enrichment:

    2. Validate: brandProfileId exists in DB, websiteUrl is a valid URL (basic URL parse check)
    3. Fetch the brand profile to get the brand name
    4. Build enrichment prompt using this template (from research):
       ```
       Research the brand "{brandName}" by thoroughly browsing their website at {websiteUrl}.

       Extract the following brand profile data:
       1. Brand Voice/Tone: How do they communicate? (2-3 sentences)
       2. Market Positioning: What's their unique value proposition? (1-2 sentences)
       3. Target Demographics: Who are they targeting? (list specific segments)
       4. Audience Interests: What topics/interests does their audience have?
       5. Customer Pain Points: What problems do they solve?
       6. Brand Colors: Extract primary, secondary, and accent hex colors from the site
       7. Mission Statement: If stated on the site

       Browse multiple pages: homepage, about page, product pages, blog. Look at their actual content, not just meta tags.

       Return ONLY valid JSON in this format:
       {
         "brandVoice": "string or null",
         "positioning": "string or null",
         "demographics": ["array"],
         "interests": ["array"],
         "painPoints": ["array"],
         "missionStatement": "string or null",
         "primaryColor": "#hex or null",
         "secondaryColor": "#hex or null",
         "accentColor": "#hex or null"
       }
       ```
    5. Call `createManusTask(enrichmentPrompt)`
    6. Save to DB via `prisma.manusTask.create()` with `taskType: 'website_enrichment'`, `brandProfileId`, `status: 'running'`
    7. Return `{ taskId: task.id, status: 'running', message: 'Website analysis started. This usually takes 3-5 minutes.' }`
    8. Add `export const dynamic = 'force-dynamic'`

    **Also create** a companion endpoint or add to the existing poll route: When a `website_enrichment` task completes, the poll endpoint (`/api/manus/[taskId]`) should also attempt to parse `resultText` as JSON and apply it to the brand profile. Add this as a post-completion step in the existing poll route (Task 1 of Plan 01 created this file):
    - After setting status to 'completed' and if `task.taskType === 'website_enrichment'` and `task.brandProfileId`:
      - Try to parse `resultText` as JSON
      - If valid JSON, do a selective merge update to the brand profile using the SAME fill-empty + append-deduplicate strategy from Phase 70 enrichment:
        - String fields (brandVoice, positioning, missionStatement): only fill if currently null/empty
        - Array fields (demographics, interests, painPoints): append new items, deduplicate
        - Color fields (primaryColor, secondaryColor, accentColor): only fill if currently null
      - If JSON parse fails, just store the raw text result (no profile update) — user can still read it
      - Log what fields were updated for debugging

    IMPORTANT: The merge MUST preserve user edits. Never overwrite non-empty fields. Follow the exact same pattern as `src/lib/enrichment/enrich-from-ads.ts` (fill-empty + append-deduplicate).
