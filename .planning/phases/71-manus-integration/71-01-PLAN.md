  <action>
    Create `src/lib/manus/types.ts` with TypeScript types for Manus API v2:
    - `ManusCreateRequest`: `{ message: { content: string }, locale?: string, hide_in_task_list?: boolean }`
    - `ManusCreateResponse`: `{ ok: boolean, request_id: string, task_id: string, task_title: string, task_url: string, share_url?: string }`
    - `ManusTaskDetail`: `{ ok: boolean, request_id: string, task: { id: string, status: string, created_at: number, updated_at: number, task_type: string } }`
    - `ManusTaskStatus`: string union `'pending' | 'running' | 'completed' | 'failed'`
    - `ManusMessagesResponse`: Use generous typing with `unknown` for unverified fields — `{ ok: boolean, messages?: Array<{ role: string, content: unknown }> }`. Add a `// TODO: refine types after live API testing` comment.

    Create `src/lib/manus/client.ts` with thin wrapper around Manus REST API v2:
    - Base URL: `https://api.manus.ai`
    - Auth header: `x-manus-api-key` from `process.env.MANUS_API_KEY`
    - `createManusTask(prompt: string)`: POST to `/v2/task.create` with `{ message: { content: prompt }, locale: 'en', hide_in_task_list: true }`. Returns typed `ManusCreateResponse`. Throw on non-ok response with status + body for debugging.
    - `getManusTask(taskId: string)`: GET `/v2/task.detail?task_id=${taskId}`. Returns typed `ManusTaskDetail`.
    - `getManusMessages(taskId: string)`: GET `/v2/task.listMessages?task_id=${taskId}`. Returns `ManusMessagesResponse`.
    - Guard: if `MANUS_API_KEY` is not set, throw a clear error message (not a silent failure).

    Create `src/lib/manus/router.ts` with keyword-based routing:
    - Export `DEEP_RESEARCH_KEYWORDS` array: `['deep research', 'deep dive', 'comprehensive analysis', 'full report', 'detailed report', 'in-depth', 'website analysis', 'brand audit', 'market research', 'competitive landscape', 'industry report', 'crawl', 'scrape website', 'analyze website', 'enrichment from website', 'auto-populate from url']`
    - Export `shouldRouteToManus(message: string, deepResearchToggle: boolean): boolean` — returns true if toggle is on OR if any keyword matches (case-insensitive includes check on lowercased message).
    - This is pure keyword matching. Do NOT use LLM classification — it adds latency and cost to every message.
  </action>
  <verify>
    - All three files compile: `npx tsc --noEmit src/lib/manus/types.ts src/lib/manus/client.ts src/lib/manus/router.ts` (or broader check)
    - router.ts: `shouldRouteToManus('do a deep dive on Nike', false)` returns true; `shouldRouteToManus('what ads is Nike running', false)` returns false; `shouldRouteToManus('anything', true)` returns true
  </verify>
  <done>
    Three files exist with typed exports. Client wraps all three Manus v2 endpoints. Router correctly identifies deep research queries via keywords and respects the toggle override.

  <action>
    Add `ManusTask` model to `prisma/schema.prisma`:
    ```
    model ManusTask {
      id              String    @id @default(cuid())
      manusTaskId     String    @unique
      brandProfileId  String?
      prompt          String
      taskType        String    @default("research")  // "research" | "website_enrichment"
      status          String    @default("pending")    // pending | running | completed | failed
      resultText      String?
      resultJson      Json?
      manusUrl        String?
      errorMessage    String?
      createdAt       DateTime  @default(now())
      updatedAt       DateTime  @updatedAt
      completedAt     DateTime?

      brandProfile    BrandProfile? @relation(fields: [brandProfileId], references: [id], onDelete: SetNull)

      @@index([status])
      @@index([brandProfileId])
    }
    ```
    Also add `manusTasks ManusTask[]` relation to the `BrandProfile` model.
    Run `npx prisma db push` to apply migration.

    NOTE: The research suggested a `userId` field but the app is open-access (no auth gates on v2). Do NOT add userId — follow the same pattern as BrandProfile which uses no auth checks.

    Create `src/app/api/manus/create/route.ts` — POST handler:
    - Parse body: `{ prompt: string, brandProfileId?: string, taskType?: 'research' | 'website_enrichment' }`
    - Validate prompt is non-empty string
    - Call `createManusTask(prompt)` from the client wrapper
    - Save to DB via `prisma.manusTask.create()` with `manusTaskId: result.task_id`, `status: 'running'`, `manusUrl: result.task_url`, `brandProfileId` if provided
    - Return `{ taskId: task.id, manusTaskId: result.task_id, status: 'running', message: 'Deep research started. This usually takes 2-5 minutes.' }`
    - On error: return 500 with error message, log full error to console
    - Add `export const dynamic = 'force-dynamic'`
    - Add `export const maxDuration = 30` (creating a task should be fast)

    Create `src/app/api/manus/[taskId]/route.ts` — GET handler:
    - Extract `taskId` from `context.params` (Next.js 16 pattern: `const { taskId } = await context.params`)
    - Look up `ManusTask` by `id` (our DB id, not manus task id)
    - If not found: return 404
    - If status is `completed` or `failed`: return cached DB result immediately (no Manus API call)
    - If status is `pending` or `running`: call `getManusTask(task.manusTaskId)` to check current status
      - If Manus says `completed`: call `getManusMessages(task.manusTaskId)`, extract the last assistant message text (iterate messages array, find last one with `role === 'assistant'`, extract string content), update DB with `status: 'completed'`, `resultText`, `resultJson: messages`, `completedAt: new Date()`. Return completed response.
      - If Manus says `failed`: update DB with `status: 'failed'`, `errorMessage`. Return failed response.
      - Otherwise: return `{ status: 'running' }` (still in progress)
    - Handle unknown Manus status values defensively (log and treat as 'running')
    - Add `export const dynamic = 'force-dynamic'`

    Helper function `extractAssistantResponse(messagesData: unknown): string` — should live in the route file or in `src/lib/manus/client.ts`. Iterates the messages array looking for the last assistant role message. If content is a string, use it directly. If content is an array, join text parts. If nothing found, return a fallback message. This function must handle unknown shapes gracefully since the exact listMessages format is not fully documented.
  </action>
