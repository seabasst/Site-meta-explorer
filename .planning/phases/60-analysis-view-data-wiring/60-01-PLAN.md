  <name>Task 1: Fix DiversityResult interface to match API response</name>
  <files>src/app/dashboard/v2/creative-lab/analysis-view.tsx</files>
  <action>
The `/api/analyze/diversity` endpoint returns this shape (see route.ts lines 511-532):

```
{
  brandName, category, totalAdsAnalyzed,
  distribution,
  diversityScores: { format, tone, journeyPhase, visualStyle, messenger, overall },
  andromedaMetrics: { creativeVolume: {...}, adFatigue: {...}, funnelBalance: {...}, hookQuality: {...}, ... },
  andromedaScore,
  classifications: [...],
  summary, biggestGap, recommendations: [...]
}
```

But `DiversityResult` interface (lines 29-38) expects `scores` (not `diversityScores`) and a simplified `andromedaMetrics` shape `{ andromedaScore, uniqueCombinations, totalAds, maxPossible }` that does not match.

Fix:

1. Update `DiversityResult` interface to match the actual API response. The interface needs at minimum:
   - `diversityScores: DiversityScores` (rename from `scores`)
   - `distribution: Record<string, Record<string, number>>` (keep as-is)
   - `andromedaMetrics: Record<string, unknown>` (or a more precise type if desired, but the component currently does not render andromedaMetrics fields directly, so a loose type is fine)
   - Add `andromedaScore: number` as a top-level field
   - Add `totalAdsAnalyzed: number`
   - Add `brandName: string`

2. Update the score pill rendering (line 255) from `diversity.scores[key]` to `diversity.diversityScores[key]`.

3. Verify that `PILLAR_PILLS` keys (`format`, `tone`, `journeyPhase`, `visualStyle`, `messenger`, `overall`) match the `diversityScores` object keys from the API — they do, so no changes needed to PILLAR_PILLS.

Do NOT change the API response shape. Only fix the client-side interface and field access.
  </action>

Run `npx tsc --noEmit` — no type errors in analysis-view.tsx.

The benchmark API (`/api/analyze/benchmark`) requires a `category` parameter — the brand's product category (e.g., "E-commerce", "Travel"). But `analysis-view.tsx` line 122 passes `brand.source` which is `'local'` or `'api'` (the search result source). The brand's actual category is available in the database (`AdLibraryBrand.category`) but not returned by the search-pages API.

Fix in three places:

**A. search-pages API (`src/app/api/search-pages/route.ts`):**
- In the `localBrands` Prisma query `select` (line 23-area), add `category: true`
- In the results mapping (line 33-area), add `category: brand.category || null` to each result object
- For Facebook API results (line 122-area), add `category: null` since FB API doesn't return category

**B. SearchResult type (`src/app/dashboard/v2/creative-lab/page.tsx`):**
- Add `category: string | null` to the `SearchResult` interface (line 31-area)

**C. AnalysisView props and benchmark call (`src/app/dashboard/v2/creative-lab/analysis-view.tsx`):**
- Add `category?: string | null` to the `AnalysisViewProps.brand` type (line 41-area)
- Change line 122 from `category: brand.source` to `category: brand.category`
- Add a guard: only call `fetchBenchmark()` if `brand.category` is truthy. If no category, skip benchmark (it's already non-fatal). This handles FB API brands that lack a category.
  </action>
