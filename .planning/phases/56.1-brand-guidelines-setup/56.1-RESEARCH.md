# Phase 56.1: Brand Guidelines Setup - Research

**Researched:** 2026-03-23
**Domain:** Brand identity form UI, Prisma schema design, R2 file uploads, color picker, prompt injection
**Confidence:** HIGH

## Summary

This phase builds a Brand Guidelines Setup page where users define their brand persona (voice, mission, target audience, visual identity) to steer AI-generated creatives. The infrastructure already exists for all key concerns: Prisma ORM for persistence, Cloudflare R2 for file uploads (with a mature `uploadToR2` helper), NextAuth for user-scoped data, and the `/api/analyze/generate-image` route where brand context can be injected into prompts.

The main work is: (1) a new `BrandGuidelines` Prisma model with one-to-one user relation, (2) a new page at `/dashboard/v2/brand-guidelines` using existing V2Shell/V2Card components, (3) a new API route `/api/brand-guidelines` for CRUD, (4) a new API route `/api/brand-guidelines/upload` for logo and reference image uploads to R2, (5) a lightweight color picker for the palette section, and (6) modifying the generate-image route to accept and inject brand context.

**Primary recommendation:** Build a standalone page (not embedded in Creative Lab) with form sections matching the Figma design, using native HTML `<input type="color">` styled with Tailwind for the color picker (zero dependencies), and reuse the existing R2 upload infrastructure for logos and reference images.

### Pattern 1: Prisma Model Design
**What:** A `BrandGuidelines` model with one-to-one relation to `User`, storing all brand identity fields.
**When to use:** Exactly one set of guidelines per user.
**Schema:**
```prisma
model BrandGuidelines {
  id        String   @id @default(cuid())
  userId    String   @unique
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  // Brand Identity
  brandVoice      String?  // Textarea: voice & personality description
  missionStatement String? // Textarea: mission statement

  // Target Audience (stored as JSON arrays for flexibility)
  demographics    String[] // Selected demographic tags: "gen-z-18-24", "millennials-25-40", etc.
  interests       String[] // Selected interest tags: "tech-early-adopters", "sustainable-living", etc.

  // Visual Identity
  logoUrl         String?  // R2 public URL for uploaded logo
  logoKey         String?  // R2 object key for logo (for deletion)
  primaryColor    String?  // Hex value, e.g. "#1235e2"
  secondaryColor  String?  // Hex value
  accentColor     String?  // Hex value

  // Reference Images (stored as JSON array of {url, key} objects)
  referenceImages Json?    // Array<{url: string, key: string, name: string}>

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

**Key design decisions:**
- `userId @unique` enforces one-to-one (one guideline set per user)
- `demographics` and `interests` as `String[]` (Prisma native array) for easy querying
- `referenceImages` as `Json` because it stores a variable-length array of objects with metadata
- Logo stored as separate `logoUrl`/`logoKey` fields (not in the JSON) because it is a single prominent asset
- All fields optional -- user can save partial guidelines and fill in over time

### Pattern 2: R2 Upload for Brand Assets
**What:** Reuse existing `uploadToR2()` from `src/lib/r2.ts` with new key prefixes for brand assets.
**When to use:** Logo uploads and reference image uploads.
**Key format:**
```typescript
// Logo: brand-assets/{userId}/logo.{ext}
// Reference images: brand-assets/{userId}/ref-{timestamp}.{ext}
function generateBrandAssetKey(userId: string, type: 'logo' | 'reference', extension: string): string {
  if (type === 'logo') return `brand-assets/${userId}/logo${extension}`;
  return `brand-assets/${userId}/ref-${Date.now()}${extension}`;
}
```

### Pattern 5: Brand Context Injection into Image Generation
**What:** When generating images, fetch the user's brand guidelines and prepend brand context to the prompt.
**When to use:** In the `/api/analyze/generate-image` route.
**Example:**
```typescript
// Build brand context string from guidelines
function buildBrandContext(guidelines: BrandGuidelines): string {
  const parts: string[] = [];
  if (guidelines.brandVoice) parts.push(`Brand personality: ${guidelines.brandVoice}`);
  if (guidelines.primaryColor) parts.push(`Brand colors: ${guidelines.primaryColor}${guidelines.secondaryColor ? ', ' + guidelines.secondaryColor : ''}${guidelines.accentColor ? ', ' + guidelines.accentColor : ''}`);
  return parts.length > 0 ? parts.join('. ') + '. ' : '';
}

// In generate-image route:
const brandContext = buildBrandContext(guidelines);
const enhancedPrompt = `Professional advertising creative, ${brandContext}${prompt}. No text, no words, no letters, clean composition`;
```

### Anti-Patterns to Avoid
- **Storing images as base64 in the database:** Use R2 for all file storage. Database should only store URLs and keys.
- **Complex nested form state:** Use react-hook-form's flat field registration. Demographics and interests are arrays of string tags, not nested objects.
- **Requiring all fields before save:** All fields should be optional. User should be able to save partial progress.
- **Building a custom color picker component:** Native `<input type="color">` combined with a hex text input is sufficient for 3 color swatches.

## Common Pitfalls

### Pitfall 1: File Upload Size Limits in Vercel
**What goes wrong:** Vercel has a 4.5MB body size limit for serverless functions. The Figma design says "max 10MB" for logos.
**Why it happens:** Vercel's default body parser limit.
**How to avoid:** Use the `export const config = { api: { bodyParser: { sizeLimit: '10mb' } } }` in the upload route, OR better: upload directly from the client to a presigned R2 URL. However, since the current R2 setup uses server-side `uploadToR2()`, the simplest approach is to keep the limit at 4.5MB for Vercel compatibility and adjust the UI copy from "max 10MB" to "max 4MB".
**Warning signs:** 413 Payload Too Large errors on upload.

### Pitfall 2: Race Condition on Save
**What goes wrong:** User clicks "Save" rapidly, creating duplicate records or losing updates.
**Why it happens:** Prisma `upsert` on `userId` should prevent duplicates, but rapid clicks can still cause confusion.
**How to avoid:** Use `upsert` (not create/update) keyed on `userId`. Disable the save button while submitting. Use react-hook-form's `isSubmitting` state.
**Warning signs:** Multiple database records for the same user.

### Pitfall 3: Orphaned R2 Objects
**What goes wrong:** User uploads a logo, then uploads a new one. The old logo file remains in R2.
**Why it happens:** No cleanup of the previous file.
**How to avoid:** Before uploading a new logo, check if `logoKey` exists and delete the old object using `deleteFromR2()` (already available in `src/lib/r2.ts`). Same for reference images when removed.
**Warning signs:** Growing R2 storage with unused files.

### Pitfall 4: Brand Context Making Prompts Too Long
**What goes wrong:** If all brand fields are filled, the brand context string could be very long, potentially degrading image generation quality.
**Why it happens:** Flux Schnell has practical prompt length limits.
**How to avoid:** Cap the brand context injection to essential elements: colors and a condensed brand voice (first 100 chars). Don't dump the entire mission statement into the image prompt.
**Warning signs:** Generated images that ignore the prompt or produce incoherent results.

### Pitfall 5: Missing User Relation in Prisma Schema
**What goes wrong:** Adding `BrandGuidelines` model without adding the reverse relation on the `User` model causes Prisma validation errors.
**Why it happens:** Prisma requires both sides of a relation to be defined.
**How to avoid:** Add `brandGuidelines BrandGuidelines?` to the `User` model alongside the new model.

### File Upload Handler (Server-Side)
```typescript
// POST /api/brand-guidelines/upload
import { auth } from '@/auth';
import { uploadToR2, deleteFromR2, extensionFromContentType } from '@/lib/r2';
import { prisma } from '@/lib/prisma';

export async function POST(request: NextRequest) {
  const session = await auth();
  if (!session?.user?.id) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  const formData = await request.formData();
  const file = formData.get('file') as File;
  const type = formData.get('type') as string; // 'logo' | 'reference'

  if (!file) {
    return Response.json({ error: 'No file provided' }, { status: 400 });
  }

  const buffer = Buffer.from(await file.arrayBuffer());
  const ext = extensionFromContentType(file.type);
  const key = type === 'logo'
    ? `brand-assets/${session.user.id}/logo${ext}`
    : `brand-assets/${session.user.id}/ref-${Date.now()}${ext}`;

  const result = await uploadToR2(key, buffer, file.type);

  return Response.json({ url: result.url, key: result.key });
}
```

## Open Questions

1. **Should brand guidelines be accessible without auth?**
   - What we know: The V2 dashboard is open-access for browsing. Auth is required for saved ads and monitored brands.
   - What's unclear: Whether brand guidelines should follow the same pattern (require auth).
   - Recommendation: Require auth. Brand guidelines are user-specific data. This follows the same pattern as SavedAd and MonitoredBrand.

2. **How many reference images to allow?**
   - What we know: Figma design shows "4/10 used" suggesting a max of 10 slots.
   - What's unclear: Storage cost implications at scale.
   - Recommendation: Cap at 10 reference images per user. Each image max 4MB. Total per user: ~40MB in R2 which is negligible.

3. **Should reference images feed into generation prompts?**
   - What we know: Flux Schnell is text-to-image only -- it does not accept reference/input images.
   - What's unclear: Whether reference images serve any purpose beyond the user's own visual reference board.
   - Recommendation: Reference images are a visual mood board for the user only. They do NOT feed into Flux Schnell generation (no image-to-image capability). Document this clearly in the UI. Future phases could use them with models that support image conditioning.
