  <name>Task 1: BrandGuidelines Prisma model + API routes</name>
  <files>
    prisma/schema.prisma
    src/app/api/brand-guidelines/route.ts
    src/app/api/brand-guidelines/upload/route.ts
  </files>
  <action>
1. Add `BrandGuidelines` model to `prisma/schema.prisma`:
   - Fields: id (cuid), userId (String @unique), brandVoice (String?), missionStatement (String?), demographics (String[]), interests (String[]), logoUrl (String?), logoKey (String?), primaryColor (String?), secondaryColor (String?), accentColor (String?), referenceImages (Json?), createdAt, updatedAt
   - Relation: `user User @relation(fields: [userId], references: [id], onDelete: Cascade)`
   - Add `brandGuidelines BrandGuidelines?` to the User model (reverse relation)

2. Run `npx prisma db push` to sync schema.

3. Create `src/app/api/brand-guidelines/route.ts`:
   - GET: Auth check via `auth()` from `@/auth`. If no session, return 401. Fetch `prisma.brandGuidelines.findUnique({ where: { userId } })`. Return `{ guidelines }` (null if none).
   - PUT: Auth check. Parse body with Zod schema: brandVoice (string max 2000, optional), missionStatement (string max 1000, optional), demographics (string array), interests (string array), primaryColor/secondaryColor/accentColor (hex regex `/^#[0-9a-fA-F]{6}$/`, optional). Use `prisma.brandGuidelines.upsert()` with userId as unique key. Return `{ guidelines }`.
   - Follow the exact auth pattern from `src/app/api/ad-library/saved/route.ts`.

4. Create `src/app/api/brand-guidelines/upload/route.ts`:
   - POST: Auth check. Parse FormData: `file` (File) and `type` ('logo' | 'reference').
   - Generate R2 key: `brand-assets/${userId}/logo${ext}` for logos, `brand-assets/${userId}/ref-${Date.now()}${ext}` for references.
   - For logo uploads: check if existing guidelines have a `logoKey`, if so call `deleteFromR2(oldKey)` before uploading new one.
   - Use `uploadToR2(key, buffer, contentType)` from `src/lib/r2.ts`.
   - Use `extensionFromContentType(file.type)` from `src/lib/r2.ts` to get the file extension.
   - Validate file type (image/png, image/jpeg, image/webp, image/svg+xml only) and size (max 4MB).
   - Return `{ url, key }`.
   - Add `export const runtime = 'nodejs'` (needed for Buffer usage).
  </action>
  <verify>
    - `npx prisma db push` succeeds without errors
    - `npx prisma studio` shows BrandGuidelines table
    - `curl -X GET http://localhost:3000/api/brand-guidelines` returns 401 (no auth)
    - Build succeeds: `npx next build` (or just check TypeScript: `npx tsc --noEmit`)
  </verify>
  <done>
    - BrandGuidelines model exists in schema with all fields
    - User model has reverse relation `brandGuidelines BrandGuidelines?`
    - GET /api/brand-guidelines returns guidelines or null
    - PUT /api/brand-guidelines upserts guidelines
    - POST /api/brand-guidelines/upload accepts file + type, uploads to R2, returns url+key
    - Logo uploads clean up previous logo from R2
  </done>
</task>

<task type="auto">
  <name>Task 2: Wire brand context into image generation</name>
  <files>
    src/app/api/analyze/generate-image/route.ts
  </files>
  <action>
Modify `src/app/api/analyze/generate-image/route.ts` to optionally inject brand context:

1. Import `auth` from `@/auth` and `prisma` from `@/lib/prisma`.

2. Add a `buildBrandContext` function that takes BrandGuidelines and returns a string:
   - Include brand voice (truncated to first 100 chars) if set
   - Include brand colors (primary, secondary, accent) if set
   - Return empty string if no guidelines or no relevant fields
   - Cap total brand context to ~200 chars to avoid degrading Flux Schnell output

3. In the POST handler, after parsing the request body:
   - Try to get the user session via `auth()` (don't require it -- generation should still work without auth)
   - If session exists, fetch `prisma.brandGuidelines.findUnique({ where: { userId: session.user.id } })`
   - Build brand context string
   - Inject into the enhanced prompt: `Professional advertising creative, ${brandContext}high quality commercial photography, ${prompt}. No text, no words, no letters, clean composition`
   - If no session or no guidelines, prompt stays exactly as it is today (backward compatible)

4. Accept optional `brandGuidelines: boolean` flag in the request body. Only fetch and inject brand context when this flag is true. This lets the client opt-in to brand-aware generation.
  </action>
  <verify>
    - `npx tsc --noEmit` passes
    - The generate-image route still works without auth (backward compatible)
    - When `brandGuidelines: true` is sent and user has guidelines, prompt includes brand context
  </verify>
  <done>
    - Generate-image route accepts optional `brandGuidelines` flag
    - When flag is true and user is authenticated with saved guidelines, brand context (voice + colors) is injected into the prompt
    - When flag is false or user has no guidelines, behavior is identical to before (no regression)
    - Brand context is capped to avoid prompt degradation
  </done>
</task>
