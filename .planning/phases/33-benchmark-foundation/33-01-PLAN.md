<task type="auto">
  <name>Task 2: Create batch-fetch utility with rate limiting</name>
  <files>src/lib/batch-fetch.ts</files>
  <action>
Create a new file `src/lib/batch-fetch.ts` that exports a function to fetch multiple ad library pages with rate limiting:

```typescript
import { fetchAdsByPageUrl, extractPageIdFromUrl, EU_COUNTRIES } from './facebook-api';
import { fetchWithRetry } from './retry';
import { buildSnapshotFromApiResult, type SnapshotData } from './snapshot-builder';

export interface BatchFetchResult {
  url: string;
  pageId: string;
  pageName: string;
  success: boolean;
  snapshot?: SnapshotData;
  error?: string;
}

export async function batchFetchPages(
  urls: string[],
  accessToken: string,
  options: { batchSize?: number; delayBetweenBatches?: number } = {}
): Promise<BatchFetchResult[]>
```

Implementation details:
1. Default batchSize = 2 (fetch 2 pages at a time to stay under rate limits)
2. Default delayBetweenBatches = 2000ms (2 seconds between batches)
3. Use `Promise.allSettled` (not Promise.all) so one failure doesn't stop others
4. Wrap each fetch in `fetchWithRetry` with maxRetries: 2, baseDelay: 2000
5. Extract pageId from URL using existing `extractPageIdFromUrl`
6. Call `fetchAdsByPageUrl` with EU_COUNTRIES and limit: 500 (pro tier)
7. On success, call `buildSnapshotFromApiResult` to get SnapshotData
8. Return array of BatchFetchResult with success/failure status per URL

Pattern reference: See facebook-api.ts lines 643-675 for batch-with-delay pattern.

Handle edge cases:
- Invalid URL (no pageId extractable) -> return {success: false, error: "Invalid URL"}
- API error -> return {success: false, error: message from API}
- Success -> return {success: true, snapshot: SnapshotData, pageName from result}

  <action>
Create two API route files:

**1. src/app/api/benchmarks/route.ts (POST and GET)**

POST /api/benchmarks - Create new benchmark:
- Require auth (use `auth()` from @/auth)
- Accept JSON body: `{ name: string, urls: string[], baselineIndex: number }`
- Validate: 2-6 URLs, baselineIndex within range
- Call `batchFetchPages(urls, process.env.FACEBOOK_ACCESS_TOKEN!)`
- Filter to successful results only
- Validate: at least 2 successful (1 baseline + 1 competitor)
- Validate: baseline URL succeeded (urls[baselineIndex] in successful results)
- Create in Prisma transaction:
  - Create BenchmarkReport with name and userId
  - Create BenchmarkBrand for each successful result, marking isBaseline=true for baselineIndex
- Return: `{ report: { id, name, brands: [...] }, failed: [...] }`
- If baseline failed: return 400 "Baseline brand failed to fetch"
- If < 2 successful: return 400 "Need at least 2 brands (1 baseline + 1 competitor)"

GET /api/benchmarks - List user's benchmarks:
- Require auth
- Return all user's BenchmarkReports with brands included
- Order by createdAt DESC

**2. src/app/api/benchmarks/[id]/route.ts (GET)**

GET /api/benchmarks/[id] - Get single benchmark:
- Require auth
- Fetch BenchmarkReport by id with brands included
- Verify userId matches session user
- Return 404 if not found or not owned
- Return: `{ report: { id, name, createdAt, brands: [...] } }`

Pattern reference: Follow src/app/api/brands/save/route.ts for auth and transaction patterns.

Important: Convert BigInt fields to string in JSON response (BigInt not serializable).
