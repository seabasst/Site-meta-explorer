  <name>Task 1: Create classify-batch.ts library with submission + result processing</name>
  <files>src/lib/classification/classify-batch.ts</files>
  <action>
Create `src/lib/classification/classify-batch.ts` exporting two functions: `submitBatchClassification` and `processBatchResults`.

**`submitBatchClassification(jobId: string)`:**
1. Fetch the ClassificationJob with `include: { brand: true }`
2. Query unclassified ads for the brand:
   ```
   prisma.adLibraryAd.findMany({
     where: { brandId: job.brandId, classification: null },
     include: {
       assets: {
         where: { assetType: "image", downloadStatus: "completed" },
         take: 1,
         select: { storedUrl: true },
       },
     },
   })
   ```
3. If no unclassified ads, update job to `status: "completed"` with `skippedAds: job.totalAds`, return early.
4. Build the system prompt via `buildClassificationPrompt()`. Build output format via `zodOutputFormat(ClassificationOutputSchema)`.
5. Map ads to batch requests array. Each request:
   - `custom_id`: the ad's database `id` (NOT adId -- the cuid primary key)
   - `params.model`: `"claude-haiku-4-5-20251001"`
   - `params.max_tokens`: 500
   - `params.system`: the system prompt (same for all -- enables prompt caching)
   - `params.messages`: single user message with optional image (from `ad.assets[0]?.storedUrl`) + text context from `buildAdContext()`
   - `params.output_config`: `{ format: outputFormat }`
6. For brands with >10,000 unclassified ads, split into chunks of 10,000 and submit multiple batches. For now, just submit the first chunk and log a warning if truncated.
7. Submit: `client.messages.batches.create({ requests })`
8. Update the job: `status: "processing"`, `anthropicBatchId: batch.id`, `batchSubmittedAt: new Date()`, `totalAds: ads.length + job.skippedAds`, `skippedAds: job.skippedAds`.
9. Return `batch.id`.

**`processBatchResults(jobId: string)`:**
1. Fetch the ClassificationJob. Must have `anthropicBatchId` and `status: "processing"`.
2. Retrieve batch status: `client.messages.batches.retrieve(job.anthropicBatchId)`
3. If `processing_status !== "ended"`, update job with progress counts from `batch.request_counts` (`classifiedAds: batch.request_counts.succeeded`, `failedAds: batch.request_counts.errored`), return `{ status: "in_progress" }`.
4. If batch ended, stream results: `for await (const result of await client.messages.batches.results(job.anthropicBatchId))`
5. For each result:
   - If `succeeded`: extract text from `result.result.message.content`, `JSON.parse()` it, validate with `ClassificationOutputSchema.parse()`. Collect into an array of `{ adId: result.custom_id, ...parsed, classifiedBy: "haiku-4.5", classificationSource: imageAssetPresent ? "vision" : "text", schemaVersion: 1 }`.
   - For `errored`, `expired`, `canceled`: increment failed count.
   - Track total input/output tokens from succeeded messages.
6. Bulk insert classifications using `prisma.adClassification.createMany({ data: classifications, skipDuplicates: true })` -- `skipDuplicates` prevents errors if cron runs twice.
7. Update the job: `status: "completed"`, `classifiedAds`, `failedAds`, `inputTokens`, `outputTokens`, `batchCompletedAt: new Date()`.
8. Fire-and-forget cost logging via `logApiCost()` with operation `"classify-batch"`.
9. Return `{ status: "completed", classified, failed }`.

For determining `classificationSource` in batch results: since we don't have the image info at result-processing time, add a helper that checks if the ad has a stored image asset. Query in bulk before the loop: `prisma.adAsset.findMany({ where: { adId: { in: adIds }, assetType: "image", downloadStatus: "completed" }, select: { adId: true } })` and build a Set of adIds that have images.

Import from `@anthropic-ai/sdk`, `@anthropic-ai/sdk/helpers/zod`, `./schemas`, `./prompt`, `./cost-tracker`, `@/lib/prisma`.
  </action>

`npx tsc --noEmit src/lib/classification/classify-batch.ts` compiles. Exports `submitBatchClassification` and `processBatchResults`.
  </verify>
  <done>classify-batch.ts exports submitBatchClassification (creates Anthropic batch from unclassified ads) and processBatchResults (streams results, persists classifications via createMany, updates job status)</done>

**`src/app/api/classify/batch/route.ts` -- POST handler to start batch classification:**

1. Parse `{ brandId }` from request body. Return 400 if missing.
2. Check for existing active job: `prisma.classificationJob.findFirst({ where: { brandId, status: { in: ["queued", "processing"] } } })`. If exists, return 409 with `{ error: "Classification already in progress", jobId: activeJob.id }`.
3. Count unclassified ads: `prisma.adLibraryAd.count({ where: { brandId, classification: null } })`.
4. Count already-classified ads: `prisma.adLibraryAd.count({ where: { brandId, classification: { isNot: null } } })`.
5. If unclassifiedCount === 0, return 200 with `{ message: "All ads already classified", total: alreadyClassified }`.
6. Estimate cost using Haiku batch pricing: `(unclassifiedCount * 500 / 1_000_000) * 0.50 + (unclassifiedCount * 200 / 1_000_000) * 2.50`. Round to 4 decimal places.
7. Create ClassificationJob: `prisma.classificationJob.create({ data: { brandId, status: "queued", totalAds: unclassifiedCount + alreadyClassified, skippedAds: alreadyClassified, estimatedCostUsd: estimatedCost } })`.
8. Call `submitBatchClassification(job.id)` in a fire-and-forget pattern (`.catch()` to update job to `failed` with error message). Do NOT await it -- return the response immediately.
9. Return 200 with `{ jobId: job.id, estimatedCost, unclassifiedAds: unclassifiedCount, alreadyClassified }`.

**`src/app/api/classify/batch/status/route.ts` -- GET handler to check job status:**

1. Parse `jobId` from URL search params. Return 400 if missing.
2. Fetch the job: `prisma.classificationJob.findUnique({ where: { id: jobId } })`. Return 404 if not found.
3. Return the job object with computed fields:
   - `progress`: `(job.classifiedAds + job.failedAds + job.skippedAds) / job.totalAds` (0-1 fraction)
   - `isComplete`: `job.status === "completed" || job.status === "failed"`
4. Return 200 with `{ job, progress, isComplete }`.

  </verify>
