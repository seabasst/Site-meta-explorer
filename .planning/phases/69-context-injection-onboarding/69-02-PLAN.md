**OnboardingPrompt component (`src/components/onboarding-prompt.tsx`):**

Create a 'use client' component that shows a dismissible banner prompting users to set up their brand profile.

- Props: `{ darkMode: boolean }`
- Uses `useSession` from next-auth to check if user is authenticated
- Two-tier visibility check:
  1. If no session, don't show (set checked=true, visible=false)
  2. If localStorage has `onboarding-prompt-dismissed`, don't show
  3. Otherwise, fetch `/api/brand-profiles` — if response has 0 profiles, show the prompt
  4. If profile count > 0, never show (even if localStorage flag exists)
- The banner has:
  - Sparkles icon on the left
  - Text: "Set up your brand profile to get personalized AI insights."
  - Link to `/dashboard/v2/onboarding` with text "Get started"
  - X button to dismiss (sets localStorage flag + hides)
- Styling: rounded-xl border, conditional dark/light mode colors using the project's design system (#1235e2 primary, dark #101322)
- Use the pattern from the research document (Pattern: Soft Onboarding Prompt Component)

**Wizard page (`src/app/dashboard/v2/onboarding/page.tsx`):**

Create a 'use client' page wrapped in V2Shell (import from `../v2-shell`). Use the project's existing `useV2` context for dark mode.

- URL-param based step tracking via `useSearchParams`: `?step=1` through `?step=5`
- Step indicator at top showing progress (step circles with labels)
- Each step renders a component from wizard-steps.tsx
- "Back" and "Next" buttons for navigation between steps
- On final step, "Next" becomes "Create Profile" — calls POST `/api/brand-profiles` with collected data
- After successful creation, redirect to `/dashboard/v2/hikaru?brand={newProfileId}` and clear the localStorage draft
- On mount, check localStorage for `brand-profile-wizard-draft` and pre-fill form if found

Steps:
1. **Brand Basics** — name (required), website URL (optional text input)
2. **Voice & Tone** — brandVoice (textarea), positioning (textarea)
3. **Target Audience** — demographics (tag input / comma-separated), interests (tag input), painPoints (tag input)
4. **Competitors** — competitor search using the same brand search pattern from the brand profile settings page (search `/api/ad-library/brands?q=...`, select brands to add)
5. **Visual Identity** — primaryColor, secondaryColor, accentColor (color picker inputs), logoUrl (text input for URL)

Draft auto-save: Use a debounced (500ms) effect that writes the current form state to localStorage key `brand-profile-wizard-draft` as JSON with a `savedAt` timestamp. On mount, load draft if it exists and is less than 7 days old.

Wrap the inner content in Suspense since useSearchParams requires it.

**Wizard steps (`src/app/dashboard/v2/onboarding/wizard-steps.tsx`):**

Export individual step components, each receiving `{ data, onChange, darkMode }` props:
- `StepBasics` — name input, optional website URL input
- `StepVoice` — brandVoice textarea (with placeholder like "Describe your brand's tone — e.g., professional yet approachable, bold and playful"), positioning textarea
- `StepAudience` — demographics, interests, painPoints as comma-separated text inputs (split into arrays on submit). Show helper text explaining each field.
- `StepCompetitors` — brand search input with dropdown results from `/api/ad-library/brands?q=...`. Selected competitors shown as chips with remove button. Store as array of `{ adLibraryBrandId, pageName }`.
- `StepVisual` — three color inputs (type="color" with hex text display), logoUrl text input

All step components use the project's existing dark/light mode pattern (conditional Tailwind classes). Match the visual style of the brand profile settings page from Phase 68.

Use the taste-skill mental model for design: clean, minimal, professional. No decorative elements. Proper spacing and hierarchy.
